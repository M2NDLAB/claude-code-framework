# scripts/ — process scripts

Only **working-method** scripts, stack-agnostic. The project's build/run scripts
(compilation, tests, startup) do NOT live here: each project adds its own.

| Script | What it does |
|---|---|
| `hooks-install.sh` | Runs the prerequisite check first (`check-prerequisites.sh --hooks`: a tool the hooks need missing or not starting stops it), then installs the local git hooks: secret scanning (gitleaks, pre-commit — with git's colour off and each textconv driver read as `cat`, so the scan reads the staged text whatever the user's git configuration, and the text git shows as binary scanned apart, in a directory only the user can read, removed however the hook ends, a SIGKILL apart), Conventional Commits (commitlint, commit-msg) and the push boundary (pre-push: it refuses a push launched from a Claude Code session, `docs/04`), active while git reads the repository's hooks directory: a hook manager that sets `core.hooksPath` after the install — husky does at every `npm install` — takes them out. Automatic code formatting is included as a **commented-out example** to adapt to the project's language. Idempotent on its own hooks (one that differs from the hook it generates — another release's, or a customised one — is saved as a `.bak` first); faced with pre-existing hooks of ANOTHER origin — including the symlinks of hook managers — it stops (override: `FORCE_OVERWRITE=1`, with a `.bak` backup), and it also stops if `core.hooksPath` is active (e.g. husky: `.git/hooks` would be ignored and the hooks would be inert). The hooks go into the repository's common git directory, shared by all its worktrees, so it runs from any of them; outside a repository it stops instead of creating a `.git`. |
| `reset-task.sh` | SURGICAL cleanup of an interrupted task: it discards ONLY the uncommitted work — staged or not, the untracked files included, the ignored ones kept — and preserves the branch and the previous commits; it says the task is discarded only when the tree then reads clean, and a step git refuses is reported as a failure. It is the cleanup of the task planning protocol (`.claude/docs/01-task-planning.md`). It refuses to operate on shared branches: the project's list is `PROTECTED_BRANCHES` in the `Makefile` (a setup slot), so run it as `make reset-task` (`YES=1` without asking); run directly, it falls back to `main develop` and warns — and refuses `--yes`. |
| `test-hooks-install.sh` | Hermetic self-test of `hooks-install.sh` (stubs for `gitleaks`/`npx` + a throwaway git repo): it runs the REAL script end-to-end and demonstrates the contract of the `FORCE_OVERWRITE=1` branch on the dangling-symlink case, then that the generated pre-push refuses agent-session pushes in every form and lets the human's through (a local `file://` bare remote), then where the hooks land — the common git directory from a linked worktree or a subdirectory, a refusal outside a repository or below its top level —, then that the install runs the prerequisite check first (a gitleaks that does not start stops it; a broken make does not), then the git configuration gitleaks reads through the generated pre-commit (the colour off, each textconv as `cat`, after the caller's own; a `GIT_CONFIG_COUNT` that is not a number stops it), then the files git shows as binary although they hold text, scanned apart (a directory of their own, only the user's, gone when the hook passes, refuses or is stopped by Ctrl-C; a file binary by its content left out), then a re-run over its own hooks (nothing saved over unchanged hooks; over another release's, a `.bak` and a message that names a difference), then a `core.hooksPath` set (a refusal that says a hook manager sets it again), without touching the real repo. Launch it with `make test-scripts`. |
| `agent-git-guard.mjs` | The PreToolUse hook (wired in `.claude/settings.json`) that keeps DELEGATED agents read-only on git: a subagent's or workflow agent's git write is refused — through Bash, PowerShell or Monitor —, whatever global options precede the subcommand and however git is spelled (`git.exe`, `Git`, a Windows path); the main session is never restricted. Claude Code's worktree tools and a git MCP server stay outside it, as `.claude/docs/04-git-workflow.md` declares. Fail-closed for delegated agents: if the guard cannot run (a crash, a missing file or `node`), their calls are blocked — the main session's are not, but each shows an `agent-git-guard: cannot run` notice. See `.claude/docs/04-git-workflow.md`, *Enforcement of the execution boundary*. |
| `test-agent-git-guard.sh` | Hermetic self-test of the guard AND of its wiring, read from `settings.json`: writes blocked, reads allowed — in PowerShell's syntax too —, main session free, the PowerShell tool off, and, with a broken guard (a crash, a missing file or `node`, unreadable input), agents blocked and the main session shown a non-blocking error whose first line is the wiring's own. |
| `repo-snapshot.sh` | Read-only fingerprint of a repository (HEAD, branch, refs, stash, worktrees, untracked files) that the main session diffs before and after delegating work to agents: any difference means stop and report. |
| `test-repo-snapshot.sh` | Hermetic self-test of `repo-snapshot.sh`: read-only (a plain `git status` as the control), every kind of trace detected and restored. |
| `check-prerequisites.sh` | Checks the framework's prerequisites, without make (`bash scripts/check-prerequisites.sh`; with `--hooks`, as `hooks-install.sh` runs it, only what the hooks need — no make): it RUNS each tool — git, bash and the POSIX userland, make, gitleaks, Node.js and npx —, compares its version with its minimum (the minimums and commitlint's pin are defined there, in one place — `hooks-install.sh` reads the pin), names the platform and whether the framework's CI verifies it, and warns when `core.autocrlf` is true and nothing holds the framework's files to LF. A tool missing, or one that does not start, fails it (exit 1, with where to install the tool), and so does gitleaks below 8.18.2, a security minimum, or with a version it cannot read; any other version below its minimum is a warning. It installs nothing. |
| `test-check-prerequisites.sh` | Hermetic self-test of `check-prerequisites.sh` (stub tools in a `PATH` of its own, throwaway repositories): tools present, missing, not starting, below a minimum — compared number by number — or with a version it cannot read; the platforms read from `uname`; the line ends. |
| `test-reset-task.sh` | Hermetic self-test of `reset-task.sh` (throwaway repositories, each proven to be one before the script runs in it): a change only staged, a staged change edited again, a change in the working tree and an untracked file all discarded, the commits and the branch untouched — under `core.autocrlf` true too —; a restore git refuses and a run outside a repository reported as failures. |

## Typical use

```bash
bash scripts/check-prerequisites.sh   # the prerequisites: each tool run and compared; installs nothing
make hooks-install      # or: bash scripts/hooks-install.sh
make test-scripts       # self-test of the scripts (hermetic: does not touch the real repo)
before="$(mktemp)"; scripts/repo-snapshot.sh > "$before"   # before delegating to agents
scripts/repo-snapshot.sh | diff "$before" -              # after: any output = stop
make reset-task         # after an interruption, before resuming a plan
```

Prerequisites (`check-prerequisites.sh` checks them): `gitleaks` and `npx` for `hooks-install.sh`, Node.js 22.12 or later for
`npx` and the guard — if `node` is missing, too old or broken, delegated agents are blocked
(fail-closed) and the main session is not. A project's own pre-push (e.g.
git-lfs's) goes in `.git/hooks/pre-push.local`: the generated pre-push runs it after the
boundary check.
